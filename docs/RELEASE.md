# Price List 10x — Release & Rollback

Last updated: 2026-08-13

## Release principle

`main` is production. The `codex/price-list-10x` branch stays isolated until explicit production approval.

Do not publish by manually copying files. Use the verified release candidate generated by CI or merge the reviewed branch only after every gate below passes.

## Pre-release checklist

- [ ] PR #1 is still based on `main` and has no unresolved review comments.
- [ ] `Quality Gate` is green on the exact head commit intended for release.
- [ ] Catalogue sync reports **145 SKUs / 8 categories** or a newer explicitly approved baseline.
- [ ] Source reconciliation reports no commercial price mismatches.
- [ ] EN / IT / FR / NL translation tests pass.
- [ ] Desktop Playwright buyer journey passes.
- [ ] Mobile Playwright journeys pass at **320 / 360 / 390 / 430 px** with no horizontal overflow.
- [ ] Quantity controls keep at least 44 px touch targets.
- [ ] WhatsApp and email quote links are generated correctly.
- [ ] Final QA screenshots have been visually reviewed.
- [ ] Release candidate contains production robots metadata, canonical URL and Open Graph URL.
- [ ] Explicit production approval has been given.

## CI artifacts

A successful run publishes four short-lived artifacts:

1. `price-list-10x-qa-screenshots`
2. `price-list-10x-playwright-report`
3. `price-list-10x-dist`
4. `price-list-10x-release-candidate`

The release candidate is generated from the verified preview build and converts the preview metadata to production-safe metadata. It does not alter `main` by itself.

## Go-live sequence

1. Confirm the final PR head SHA.
2. Confirm the corresponding GitHub `Quality Gate` completed successfully.
3. Review the final desktop and mobile QA screenshots from that same run.
4. Confirm `main` has not moved unexpectedly. If it has, rebase/reconcile and rerun the full gate.
5. Obtain explicit production approval.
6. Merge the reviewed PR using the repository's normal merge method.
7. Wait for the Vercel production deployment tied to the merged `main` commit.
8. Verify the production URL on desktop and mobile.
9. Smoke-test: search SKU, quantity tier, add/update quote, locale switch, WhatsApp link and email link.
10. Keep the previous READY deployment available until the smoke test is complete.

## Rollback triggers

Rollback immediately if any of the following appears after release:

- catalogue count unexpectedly drops;
- a verified SKU disappears;
- price/unit, price/case, subtotal or discount tier diverges;
- quote actions fail;
- mobile horizontal overflow blocks the buyer flow;
- production returns a broken build or missing assets.

## Rollback procedure

1. In Vercel, identify the most recent previously healthy production deployment for `price-list`.
2. Promote/redeploy that known-good deployment using Vercel's rollback/redeploy controls.
3. If the issue came from the merged code, revert the release commit on `main` rather than editing production files manually.
4. Verify the restored production URL with the same smoke-test flow.
5. Fix the issue again on an isolated branch and require the full CI gate before another release.

## Data-source failure behaviour

The runtime rejects a live catalogue that silently omits SKUs present in the verified build snapshot. If the public live feed is incomplete or unavailable, the UI falls back to the most recent verified catalogue instead of showing a smaller catalogue silently.

Build-time catalogue generation reads the current shared Google Sheet directly, not the stale published-web CSV path.

## Preview limitation

The current Vercel project is connected to GitHub but its observed deployments are production deployments from `main`; no automatic branch preview is currently being generated for `codex/price-list-10x`.

Until Vercel Git preview deployments are enabled for non-production branches, GitHub CI artifacts plus Playwright screenshots are the protected preview mechanism. Enabling that project setting is safe to do later, but it is intentionally not simulated by deploying over production.
